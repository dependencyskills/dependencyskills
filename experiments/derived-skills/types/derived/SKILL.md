# io.github.aughtone:types

Plain value types for Kotlin Multiplatform common code. Everything is under the package `io.github.aughtone.types`, one sub-package per area [src: commonMain/io/github/aughtone/types/financial/Money.kt:1] [src: commonMain/io/github/aughtone/types/uri/Url.kt:1]; each area below names its sub-package so the import is not a guess.

## What it solves

**Money and currencies** (`financial`). An amount that carries its currency and adds, subtracts, compares and rounds to cents without floating-point drift: the amount is held as an arbitrary-precision decimal [src: commonMain/io/github/aughtone/types/financial/Money.kt:10] and can track fractions of a cent [src: commonMain/io/github/aughtone/types/financial/Money.kt:11]. ISO 4217 currencies are looked up by three-letter code [src: commonMain/io/github/aughtone/types/financial/Currency.functions.kt:12], by locale [src: commonMain/io/github/aughtone/types/financial/Currency.functions.kt:52] or by a fragment of their name [src: commonMain/io/github/aughtone/types/financial/Currency.functions.kt:41], or listed in full [src: commonMain/io/github/aughtone/types/financial/Currency.functions.kt:32]; each carries its code, numeric code, decimal digits, name and symbol [src: commonMain/io/github/aughtone/types/financial/Currency.kt:28].

**Big numbers** (`number`). `BigInteger` and `BigDecimal` written in pure Kotlin so they behave identically on JVM, JS, Wasm and Native [src: commonMain/io/github/aughtone/types/number/BigInteger.kt:11], with their own `RoundingMode` enum [src: commonMain/io/github/aughtone/types/number/RoundingMode.kt:6]. `BankersValue` is a simpler alternative: a `Long` count of cents whose arithmetic rounds half to even [src: commonMain/io/github/aughtone/types/number/BankersValue.kt:10].

**Locales and language tags** (`locale`). A `Locale` data class of language, region, script and variant codes plus a display name [src: commonMain/io/github/aughtone/types/locale/Locale.kt:32], built from a BCP 47 tag such as `en-US` or `zh-Hans-CN` [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:100]. It reads the device's current locale [src: commonMain/io/github/aughtone/types/locale/Locale.kt:85], lists the bundled locales [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:178], searches them by name [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:187], and renders a locale's name in another language [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:209].

**Positions and measurements** (`quantitative`). `Coordinates` (latitude, longitude) [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:42], `Distance` in metres [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:19], `Speed` in metres per second [src: commonMain/io/github/aughtone/types/quantitative/Speed.kt:19], `Altitude` in metres [src: commonMain/io/github/aughtone/types/quantitative/Altitude.kt:27] and `Azimuth`, a compass heading in degrees [src: commonMain/io/github/aughtone/types/quantitative/Azimuth.kt:25], each with an optional accuracy. Subtracting two coordinates gives the great-circle distance by the haversine formula [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:57], and a point can be moved by a distance along a bearing [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:106]. `Telemetry` bundles a position with optional heading, speed, altitude and a timestamp [src: commonMain/io/github/aughtone/types/quantitative/Telemetry.kt:17].

**GeoJSON** (`geo`). The RFC 7946 object model as `@Serializable` classes: `GeoPoint` [src: commonMain/io/github/aughtone/types/geo/GeoPoint.kt:27], `GeoMultiPoint` [src: commonMain/io/github/aughtone/types/geo/GeoMultiPoint.kt:8], `GeoLineString` [src: commonMain/io/github/aughtone/types/geo/GeoLineString.kt:8], `GeoMultiLineString` [src: commonMain/io/github/aughtone/types/geo/GeoMultiLineString.kt:8], `GeoPolygon` [src: commonMain/io/github/aughtone/types/geo/GeoPolygon.kt:8], `GeoMultiPolygon` [src: commonMain/io/github/aughtone/types/geo/GeoMultiPolygon.kt:8], `GeometryCollection` [src: commonMain/io/github/aughtone/types/geo/GeometryCollection.kt:11], `GeoFeature` [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:38] and `GeoFeatureCollection` [src: commonMain/io/github/aughtone/types/geo/GeoFeatureCollection.kt:11], with a `GeoBoundingBox` helper [src: commonMain/io/github/aughtone/types/geo/GeoBoundingBox.kt:31] and polygon winding checks [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:70].

**Web addresses and identifiers** (`uri`). Parsing a string into a `Uri` [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:81], a `Url` with host, port and user information broken out [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:105], a `Urn` [src: commonMain/io/github/aughtone/types/uri/Urn.kt:143] or an RFC 5870 `geo:` link [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:169]; assembling a URL from parts with `UrlBuilder` [src: commonMain/io/github/aughtone/types/uri/UrlBuilder.kt:29]; and percent-encoding or form-encoding a string with `UrlEncoder` [src: commonMain/io/github/aughtone/types/uri/UrlEncoder.kt:16].

**Success or failure as a value** (`outcome`). `Outcome<T>` covers the same ground as `kotlin.Result` [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:9] but is a sealed class, so it compiles to an ordinary class hierarchy on every target and callers in other languages can branch on it [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:19].

**Units and two small collections** (`units`, `util`). `UnitOfMeasure` is an enum of units with their symbols [src: commonMain/io/github/aughtone/types/units/UnitOfMeasure.kt:32] and `MetricPrefix` the SI prefixes with their power of ten [src: commonMain/io/github/aughtone/types/units/MetricPrefix.kt:13]. `LazyMap` computes each value on first access and caches it [src: commonMain/io/github/aughtone/types/util/LazyMap.kt:11]; `BitSet` is a compact fixed-size set of booleans [src: commonMain/io/github/aughtone/types/util/BitSet.kt:10].

## How it is meant to be used

**Money: name the currency, and mind which number type you pass.** A `Double` is an amount in major units [src: commonMain/io/github/aughtone/types/financial/Money.kt:105]; a `Long` is a count of minor units [src: commonMain/io/github/aughtone/types/financial/Money.kt:94].

```kotlin
import io.github.aughtone.types.financial.Money
import io.github.aughtone.types.financial.currencyFor

val usd = currencyFor("USD") ?: error("unknown currency")
val price = Money(19.99, usd)      // Double: 19.99
val fee = Money(250L, usd)         // Long: 250 minor units, 2.50
val total = price + fee            // 22.49
val share = total / 3L             // Long here is a plain divisor
val cents: Long = total.minorUnits // 2249
```

Adding and subtracting keep full precision [src: commonMain/io/github/aughtone/types/financial/Money.kt:115]. Dividing by a scalar is exact when the quotient terminates, and otherwise rounds half-even at a scale of `max(value.scale, currency.digits) + 2` [src: commonMain/io/github/aughtone/types/financial/Money.kt:177], so `share` above holds more digits than the currency prints. `minorUnits` is where rounding to the currency's own digits happens, half-even [src: commonMain/io/github/aughtone/types/financial/Money.kt:81].

**Untrusted text: parse with the `…OrNull` form, or wrap the throwing form in `runOutcome`.** Each parser has both: `uri`/`uriOrNull` [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:94], `url`/`urlOrNull` [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:158], `geoUri`/`geoUriOrNull` [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:209], `urn`/`urnOrNull` [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:212]. `runOutcome { … }` turns anything thrown into an `Outcome.Failure` [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:209], except a `CancellationException`, which it re-throws [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:207].

```kotlin
import io.github.aughtone.types.outcome.Outcome
import io.github.aughtone.types.outcome.runOutcome
import io.github.aughtone.types.uri.url

when (val outcome = runOutcome { url(input) }) {
    is Outcome.Success -> open(outcome.data)     // Url: scheme, host, port, path, query, fragment
    is Outcome.Failure -> report(outcome.message)
}
```

**Positions: build `Coordinates` with named arguments, and convert to GeoJSON with `toGeoPoint()`.**

```kotlin
import io.github.aughtone.types.geo.toGeoPoint
import io.github.aughtone.types.quantitative.*

val here = Coordinates(latitude = 45.42, longitude = -75.69)
val there = Coordinates(latitude = 43.65, longitude = -79.38)
val apart: Distance = here - there                               // haversine, metres
val east = here.plus(1000.0.toDistance(), 90.0.toAzimuth())      // 1 km due east
val point = here.toGeoPoint()                                    // position [-75.69, 45.42]
```

`toGeoPoint()` does the reordering to GeoJSON's longitude-first position [src: commonMain/io/github/aughtone/types/geo/GeoPoint.extensions.kt:29]. `Int`, `Long` and `Double` have `toDistance`, `toSpeed`, `toAltitude` and `toAzimuth` extensions [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:165] [src: commonMain/io/github/aughtone/types/quantitative/Speed.kt:151] [src: commonMain/io/github/aughtone/types/quantitative/Altitude.kt:93] [src: commonMain/io/github/aughtone/types/quantitative/Azimuth.kt:118].

**Locales: pick the lookup by how strict it should be.** `localeFor(tag)` is an exact match against the bundled table and returns `null` otherwise [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:49]. `resolveLocale(tag)` falls back by dropping subtags from the right, so `en-GB-scouse` tries `en-GB`, then `en` [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:64], and then asks the platform [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:83]. `parseLocale(tag)` always returns a `Locale`, splitting the tag by hand when the table has no entry [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:100]. All three accept `_` as a separator and normalize case [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:12], and map the legacy codes `iw`, `in` and `ji` to `he`, `id` and `yi` [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:5]. `currencyFor(locale)` then gives that locale's currency, or `null` [src: commonMain/io/github/aughtone/types/financial/Currency.functions.kt:52].

**Serialization.** The value types are `@Serializable` for kotlinx.serialization with explicit serial names [src: commonMain/io/github/aughtone/types/financial/Money.kt:29] [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:41] [src: commonMain/io/github/aughtone/types/uri/Url.kt:21]. The GeoJSON classes are a sealed hierarchy whose `type` member is the class discriminator [src: commonMain/io/github/aughtone/types/geo/GeoJson.kt:9], and each subclass's serial name is its RFC 7946 type name, such as `Point` [src: commonMain/io/github/aughtone/types/geo/GeoPoint.kt:26] or `Feature` [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:37].

## Invariants and traps

### Money and numbers

**A `Long` means minor units when constructing, adding or subtracting, and a plain multiplier when multiplying or dividing.** `Money(1000L, usd) + 250L` is 10.00 plus 2.50 [src: commonMain/io/github/aughtone/types/financial/Money.kt:188], while `Money(1000L, usd) * 2L` is 20.00 [src: commonMain/io/github/aughtone/types/financial/Money.kt:218]. A `Long` is scaled by the currency's digits [src: commonMain/io/github/aughtone/types/financial/Money.kt:95], so the symptom of confusing the two is an amount off by that factor — a hundredfold for a two-digit currency. `plusMinorUnits` and `minusMinorUnits` say which is meant [src: commonMain/io/github/aughtone/types/financial/Money.kt:205] [src: commonMain/io/github/aughtone/types/financial/Money.kt:212].

**Leaving out the currency reads the device's locale, and can throw.** Every `Money` constructor, `Money.zero()` and `toMoney()` default the currency to `Currency.current` [src: commonMain/io/github/aughtone/types/financial/Money.kt:34] [src: commonMain/io/github/aughtone/types/financial/Money.kt:94] [src: commonMain/io/github/aughtone/types/financial/Money.kt:105] [src: commonMain/io/github/aughtone/types/financial/Money.kt:271] [src: commonMain/io/github/aughtone/types/financial/Money.extensions.kt:12], which throws `IllegalArgumentException` — "Your locale could not be found, or there was no currency mapped to it…" — when no currency is mapped to the current locale [src: commonMain/io/github/aughtone/types/financial/Currency.kt:99]. The mapping is keyed by language-and-region tags such as `en-US` [src: commonMain/io/github/aughtone/types/financial/LocaleToCurrency.resource.kt:9], and holds no key that is a bare language [uncited], so a locale without a region resolves to nothing. `Currency.currentOrNull` reports the same lookup as `null` [src: commonMain/io/github/aughtone/types/financial/Currency.kt:112]. An amount built with an explicit currency does not depend on the device it runs on [uncited].

**Mixing currencies throws, including when sorting.** `plus`, `minus`, `times` and `div` between two `Money` values require matching currencies [src: commonMain/io/github/aughtone/types/financial/Money.kt:114] [src: commonMain/io/github/aughtone/types/financial/Money.kt:124] [src: commonMain/io/github/aughtone/types/financial/Money.kt:138] [src: commonMain/io/github/aughtone/types/financial/Money.kt:148], and so does `compareTo` [src: commonMain/io/github/aughtone/types/financial/Money.kt:70]. The symptom of sorting or taking the `max` of a mixed list is `IllegalArgumentException`: "Cannot compare USD to EUR: amounts in different currencies have no ordering." [src: commonMain/io/github/aughtone/types/financial/Money.kt:71]

**Results are not rounded to the currency's digits for you.** A `Money` keeps sub-minor precision [src: commonMain/io/github/aughtone/types/financial/Money.kt:11], and a non-terminating division keeps two guard digits beyond the currency's [src: commonMain/io/github/aughtone/types/financial/Money.kt:178]. The symptom, for `share` in the example above, is `7.4967` where `7.50` was expected: 22.49 divided by 3 at scale 4 [src: commonMain/io/github/aughtone/types/financial/Money.kt:253]. `minorUnits` rounds [src: commonMain/io/github/aughtone/types/financial/Money.kt:81], as does `value.setScale(currency.digits, RoundingMode.HALF_EVEN)` [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:297].

**`Money / Money` is a `Double` ratio, not an amount** [src: commonMain/io/github/aughtone/types/financial/Money.kt:147], computed in floating point [src: commonMain/io/github/aughtone/types/financial/Money.kt:149]. `Money * Money` does return a `Money`, which the source itself calls an unusual operation — a scalar multiplier is almost always what is wanted [src: commonMain/io/github/aughtone/types/financial/Money.kt:132].

**`Money` equality ignores scale; `BigDecimal` equality does not.** `Money(5.1, usd)` equals `Money(5.10, usd)` [src: commonMain/io/github/aughtone/types/financial/Money.kt:15], but `BigDecimal` compares unscaled value and scale [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:112], so `2.0` and `2.00` are not `==` although `compareTo` returns `0` [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:46]. The symptom is an equality assertion on `.value` failing for two amounts that are equal as `Money`; `value.scale` is what differs [src: commonMain/io/github/aughtone/types/financial/Money.kt:22]. Two equal `Money` values can also serialize differently, because the scale given is preserved [src: commonMain/io/github/aughtone/types/financial/Money.kt:20].

**`Currency` equality is the ISO code alone** [src: commonMain/io/github/aughtone/types/financial/Currency.kt:63]. `usd.copy(symbol = "US$") == usd` is `true` [src: commonMain/io/github/aughtone/types/financial/Currency.kt:58], so a `Set` or map keyed by currency keeps one entry per code whatever the other fields say.

**A serialized `Money` is a nested object, not a decimal string.** `Money` serializes `value` and `currency` [src: commonMain/io/github/aughtone/types/financial/Money.kt:31] [src: commonMain/io/github/aughtone/types/financial/Money.kt:33]; the `BigDecimal` value serializes as `unscaledValue` and `scale` [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:19] [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:21]; the `BigInteger` inside that as `signum` and a `magnitude` array of 32-bit words [src: commonMain/io/github/aughtone/types/number/BigInteger.kt:20] [src: commonMain/io/github/aughtone/types/number/BigInteger.kt:23]; and the currency as all of its fields [src: commonMain/io/github/aughtone/types/financial/Currency.kt:29]. No custom serializer flattens any of this [uncited]. The symptom is a payload consumer expecting `"19.99"` and receiving an object [uncited].

**`currencyFor(code)` is an exact-key lookup** [src: commonMain/io/github/aughtone/types/financial/Currency.functions.kt:12], and the keys are upper-case ISO codes [src: commonMain/io/github/aughtone/types/financial/Currency.resource.kt:171]; a lower-case code returns `null`. `currencyForNative` asks the platform instead and returns different data on different platforms [src: commonMain/io/github/aughtone/types/financial/Currency.functions.kt:20] — on Apple targets the numeric code is `-1` when the bundled table lacks the currency [src: appleMain/io/github/aughtone/types/financial/Currency.functions.apple.kt:33], and on the JVM the name is the platform's display name [src: jvmMain/io/github/aughtone/types/financial/Currency.functions.jvm.kt:15].

**These are not `java.math` classes.** `BigDecimal` and `BigInteger` here are the library's own [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:18] [src: commonMain/io/github/aughtone/types/number/BigInteger.kt:19], and `Money.value` is this `BigDecimal` [src: commonMain/io/github/aughtone/types/financial/Money.kt:3]. Much of the JDK surface is absent: there is no `MathContext`, `pow`, `abs`, `negate`, `remainder`, `precision`, `toPlainString` or `toBigInteger` on `BigDecimal`, and no public `pow`, `abs`, `gcd`, `sqrt` or `toByteArray` on `BigInteger` [uncited]. Negation is unary minus on both [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:180] [src: commonMain/io/github/aughtone/types/number/BigInteger.kt:181], and the sign is the `signum` property, not a function [src: commonMain/io/github/aughtone/types/number/BigInteger.kt:21]. The symptom is an unresolved reference on a call that exists in the JDK [uncited].

**`BigDecimal` division with `/` must be exact.** `a / b` is `divide(b)` [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:179], which throws `ArithmeticException` — "Non-terminating decimal expansion; no exact representable decimal result." — for a quotient such as `1 / 3` [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:233]. `divide(other, scale, roundingMode)` names the scale and rounding [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:250]. Likewise `setScale(n)` with one argument never rounds and throws "Rounding necessary" if a non-zero digit would be dropped [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:285] [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:311].

**A `Double` becomes the decimal it prints as.** `BigDecimal.valueOf(0.1)` goes through the shortest round-tripping string and is `0.1` [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:354], and the `BigDecimal(Double)` constructor delegates to it [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:37]. `valueOfExact` gives the exact binary value instead, `0.1000000000000000055511151231257827021181583404541015625` [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:352], and throws `ArithmeticException` for `NaN` or an infinity [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:364]. `toString` never uses scientific notation except for a negative scale, which prints as `123E+2` [src: commonMain/io/github/aughtone/types/number/BigDecimal.kt:136].

**`BigInteger.toInt()` and `toLong()` truncate silently** to the low-order bits when the value does not fit [src: commonMain/io/github/aughtone/types/number/BigInteger.kt:234] [src: commonMain/io/github/aughtone/types/number/BigInteger.kt:244]. `rem` (and `%`) takes the sign of the dividend while `mod` is always non-negative: `(-7).mod(3)` is `2`, `(-7).rem(3)` is `-1` [src: commonMain/io/github/aughtone/types/number/BigInteger.kt:278]. Division by zero throws `ArithmeticException` [src: commonMain/io/github/aughtone/types/number/BigInteger.kt:265].

**`BankersValue` counts cents, and its two factories disagree on units.** The constructor and `fromLong` take cents — `100` is 1.00 [src: commonMain/io/github/aughtone/types/number/BankersValue.kt:13] [src: commonMain/io/github/aughtone/types/number/BankersValue.kt:87] — while `fromDouble` takes major units and rounds to the nearest cent [src: commonMain/io/github/aughtone/types/number/BankersValue.kt:98]. `toLong()` returns cents and `toDouble()` major units [src: commonMain/io/github/aughtone/types/number/BankersValue.kt:74] [src: commonMain/io/github/aughtone/types/number/BankersValue.kt:77]. Multiplying two values treats both as amounts and divides the product by 100 [src: commonMain/io/github/aughtone/types/number/BankersValue.kt:26]. It carries no currency [uncited].

### Positions and measurements

**Latitude and longitude change places between types.** `Coordinates` takes latitude first [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:20], and so does `GeoUri` [src: commonMain/io/github/aughtone/types/uri/GeoUri.kt:26]; `GeoPoint` takes longitude first because RFC 7946 requires it [src: commonMain/io/github/aughtone/types/geo/GeoPoint.kt:34], and `DoubleArray.toCoordinates()` reads index 0 as longitude [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:152]. Both values are `Double`, so transposing them compiles [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:22]. The symptom is a point in the wrong hemisphere — or, going into `Coordinates`, an `IllegalArgumentException` "Latitude must be between -90 and 90." when a longitude lands in the latitude slot [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:51]. `GeoPoint` checks only that it has at least two elements [src: commonMain/io/github/aughtone/types/geo/GeoPoint.kt:79], so the mistake is silent there. There is no `GeoPoint`-to-`Coordinates` extension [uncited]; `point.latitude` and `point.longitude` are the named accessors [src: commonMain/io/github/aughtone/types/geo/GeoPoint.kt:70] [src: commonMain/io/github/aughtone/types/geo/GeoPoint.kt:65].

**`accuracy` does not mean the same thing on every type.** On `Distance` and `Speed` it is a fraction of the measurement — `0.05` is five percent [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:11] [src: commonMain/io/github/aughtone/types/quantitative/Speed.kt:11]. On `Coordinates` and `Altitude` it is metres [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:35] [src: commonMain/io/github/aughtone/types/quantitative/Altitude.kt:16], and on `Azimuth` degrees [src: commonMain/io/github/aughtone/types/quantitative/Azimuth.kt:16]. `Distance(100.0, accuracy = 5f)` therefore claims five hundred percent, not five metres [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:12]; the symptom is an error radius far larger than the measurement. The `Distance` returned by subtracting two `Coordinates` carries a relative accuracy, except when the two points coincide, where it is the absolute sum in metres [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:59].

**Quantities that cannot be negative throw rather than clamp.** `Distance - Distance` and `Speed - Speed` throw `IllegalArgumentException` when the right side is larger [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:70] [src: commonMain/io/github/aughtone/types/quantitative/Speed.kt:70], with a message that ends "a Distance cannot be negative." or "a Speed cannot be negative." [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:71] [src: commonMain/io/github/aughtone/types/quantitative/Speed.kt:71] — as do a negative value at construction [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:25] [src: commonMain/io/github/aughtone/types/quantitative/Speed.kt:24] and a negative scalar for `Speed` [src: commonMain/io/github/aughtone/types/quantitative/Speed.kt:103]. Dividing by zero throws `ArithmeticException` [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:120] [src: commonMain/io/github/aughtone/types/quantitative/Speed.kt:122]. `Distance / Distance` is a `Double` ratio [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:99]; `Distance` has `/ Int` [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:119] but no multiplication and no division by a `Double` [uncited].

**`Azimuth` rejects out-of-range input instead of wrapping it.** Construction accepts only 0 to 360 degrees [src: commonMain/io/github/aughtone/types/quantitative/Azimuth.kt:30], with 360 stored as 0 [src: commonMain/io/github/aughtone/types/quantitative/Azimuth.kt:43]; a raw bearing of `-10.0` or `450.0` throws `IllegalArgumentException`: "Azimuth must be between 0 and 360 degrees." [src: commonMain/io/github/aughtone/types/quantitative/Azimuth.kt:30] Only arithmetic between azimuths wraps around [src: commonMain/io/github/aughtone/types/quantitative/Azimuth.kt:58].

**Three operations on `Coordinates` that read alike.** `a - b` is the distance between them [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:67]; `-a` is the antipodal point [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:133]; moving a point is `a.plus(distance, bearing)`, a two-argument call that the `+` operator cannot reach [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:106]. `Coordinates.add(deltaLatitude, deltaLongitude)` is plain addition with no wrapping at the poles or the date line [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.extensions.kt:9], so a result out of range fails the constructor's range check [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.kt:52], and the result is built without the original accuracy [src: commonMain/io/github/aughtone/types/quantitative/Coordinates.extensions.kt:25].

**Units are fixed.** `Distance` and `Altitude` are metres [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:19] [src: commonMain/io/github/aughtone/types/quantitative/Altitude.kt:27], `Speed` is metres per second [src: commonMain/io/github/aughtone/types/quantitative/Speed.kt:19], and `Telemetry.timestamp` is milliseconds since the epoch with `0` meaning unavailable [src: commonMain/io/github/aughtone/types/quantitative/Telemetry.kt:14]. Nothing converts to kilometres, miles, feet or km/h [uncited].

### GeoJSON

**Geometry constructors validate structure, and so does deserialization.** A `GeoLineString` needs at least two positions [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:29]; each polygon ring needs at least four and must end where it starts [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:36] [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:40]. The checks sit in `init`, so they also run when decoding [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:6]. The symptom is `IllegalArgumentException` — "a linear ring must be closed…" — thrown while constructing or decoding a document [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:41].

**The `GeoPolygon` constructor does not check winding; `geoPolygon(...)` does.** Winding is left unchecked in `init` so that foreign documents still parse [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:10]. `geoPolygon(coordinates)` throws `IllegalArgumentException` when a ring is wound the wrong way — the exterior must be counter-clockwise and holes clockwise, and a ring enclosing no area is let through [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:116] [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:118]; `geoPolygonRewinding(coordinates)` accepts any winding and corrects it [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:132]; `polygon.rewound()` corrects one already parsed [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:93]; `polygon.windingOf(ringIndex)` reports it [src: commonMain/io/github/aughtone/types/geo/GeoValidation.kt:70].

**`GeoFeature.properties` is a `JsonObject`, not a `Map<String, String>`** [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:42], and `id` is a `JsonPrimitive` that must be a string or a number [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:44] [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:50]. `geometry` has no default and must be passed, as `null` if there is none [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:40]. Values are read with `stringProperty`, `intProperty`, `doubleProperty`, `booleanProperty`, `objectProperty` and `arrayProperty` [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:65] [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:75] [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:79] [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:83] [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:87] [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:90]; `stringProperty` returns `null` both for an absent key and for JSON `null` [src: commonMain/io/github/aughtone/types/geo/GeoFeature.kt:62].

**`GeoBoundingBox` is not a geometry.** It is a helper, not a `GeoGeometry` [src: commonMain/io/github/aughtone/types/geo/GeoBoundingBox.kt:13]; every GeoJSON object's `bbox` member is a `List<Double>?` [src: commonMain/io/github/aughtone/types/geo/GeoJson.kt:19], which `toBbox()` returns [src: commonMain/io/github/aughtone/types/geo/GeoBoundingBox.kt:90]. `toDoubleArray()` gives the same numbers as a `DoubleArray`, which will not assign to `bbox` [src: commonMain/io/github/aughtone/types/geo/GeoBoundingBox.kt:20]. Its list constructor accepts exactly four or six numbers [src: commonMain/io/github/aughtone/types/geo/GeoBoundingBox.kt:54].

**One class breaks the naming pattern:** the geometry collection is `GeometryCollection`, without the `Geo` prefix the others carry [src: commonMain/io/github/aughtone/types/geo/GeometryCollection.kt:11].

### Locales

**`Locale` cannot be built from codes alone.** `displayName` has no default [src: commonMain/io/github/aughtone/types/locale/Locale.kt:42], so `Locale("en", "US")` does not compile; `parseLocale("en-US")` is the way to get one from a tag [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:100]. `parseLocale` never fails: for a tag the bundled table lacks it returns a `Locale` whose `displayName` is the normalized tag itself [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:132]. The symptom is a raw tag such as `xx-YY` shown where a language name was expected [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:132].

**`Locale.current` throws when the platform reports nothing** [src: commonMain/io/github/aughtone/types/locale/Locale.kt:86]; `Locale.currentOrNull` returns `null` instead [src: commonMain/io/github/aughtone/types/locale/Locale.kt:101]. Whether that can happen depends on the target. On JVM, Android and Apple the lookup ends by parsing whatever tag the platform gave, so it always produces a `Locale` [src: jvmMain/io/github/aughtone/types/locale/Locale.functions.jvm.kt:68] [src: androidMain/io/github/aughtone/types/locale/Locale.functions.android.kt:51] [src: appleMain/io/github/aughtone/types/locale/Locale.functions.apple.kt:59]. On Kotlin/JS the tag comes from `window.navigator.language` and a failure reading it yields `null` [src: jsMain/io/github/aughtone/types/locale/Locale.functions.js.kt:11]; on Wasm the same when there is no `window` [src: wasmJsMain/io/github/aughtone/types/locale/Locale.functions.wasmJs.kt:11]; on Linux when the `LANG` environment variable is unset [src: linuxMain/io/github/aughtone/types/locale/Locale.functions.linux.kt:12]. `currentNativeLocale(fallbackTag)` takes a tag to use in that case [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:171].

**`resolveLocale` returning `null` for an unknown tag is not portable.** Its last step is the platform lookup [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:83]. On JS, Wasm and Linux that is the strict table lookup again [src: jsMain/io/github/aughtone/types/locale/Locale.functions.js.kt:18] [src: wasmJsMain/io/github/aughtone/types/locale/Locale.functions.wasmJs.kt:6] [src: linuxMain/io/github/aughtone/types/locale/Locale.functions.linux.kt:19], so an unknown tag gives `null`; on JVM and Android it always constructs a `Locale` [src: jvmMain/io/github/aughtone/types/locale/Locale.functions.jvm.kt:8] [src: androidMain/io/github/aughtone/types/locale/Locale.functions.android.kt:8]. `localeFor` is the lookup that is strict on every target [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:57].

**A localized name may silently be the English one.** `localizedDisplayName(displayIn)` falls back to the English `displayName` when the platform has no translation [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:210]; `localizedDisplayNameOrNull` returns `null` there instead [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:232]. Both default `displayIn` to `Locale.current`, which can throw [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:227]. A browser and a native platform disagree on the wording of roughly 40% of the pairs both can name [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:250], so rendered names do not belong in cache keys or snapshot tests [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:252].

**`displayName` takes part in `Locale` equality.** `Locale` is a data class with `displayName` in its constructor [src: commonMain/io/github/aughtone/types/locale/Locale.kt:32] [src: commonMain/io/github/aughtone/types/locale/Locale.kt:42] and no `equals` of its own [uncited], while the name a platform lookup supplies is the platform's [src: jvmMain/io/github/aughtone/types/locale/Locale.functions.jvm.kt:13] and the bundled table's is English [src: commonMain/io/github/aughtone/types/locale/Locale.resource.kt:70]. Two locales for one tag from different lookups can therefore be unequal; `languageTag` is the stable thing to compare [src: commonMain/io/github/aughtone/types/locale/Locale.kt:57].

### URLs, URIs and URNs

**`url(...)` needs an authority.** A string such as `mailto:someone@example.com` has none and throws `UriParseException` — "a URL needs an authority" [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:109]; `uri(...)` parses it [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:81]. A port outside 0..65535 is rejected [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:153], and an absent port is parsed as `null` rather than filled in with the scheme's default [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:131].

**Not every failure is a `UriParseException`.** It extends `IllegalArgumentException` [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:24], and `uri`, `url` and `geoUri` throw it [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:79] [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:103] [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:167]. But `urn(...)` builds a `Urn` whose constructor rejects an invalid namespace with a plain `IllegalArgumentException` [src: commonMain/io/github/aughtone/types/uri/Urn.kt:50], which is why `urnOrNull` catches the wider type [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:212]; and `Uri.toUrl()` and `Uri.toUrn()` throw plain `IllegalArgumentException` too [src: commonMain/io/github/aughtone/types/uri/Uri.kt:137] [src: commonMain/io/github/aughtone/types/uri/Uri.kt:115]. The symptom is a `catch (e: UriParseException)` that an invalid URN passes straight through, since `urn` constructs the `Urn` outside any such catch [src: commonMain/io/github/aughtone/types/uri/Urn.kt:181].

**Parsing normalizes almost nothing.** `uri` lowercases the scheme [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:75] and `url` the scheme and host [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:100]; percent-encoding is preserved exactly and dot segments are not resolved [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:76]. `query` is the raw string after `?` [src: commonMain/io/github/aughtone/types/uri/Url.kt:14]; nothing splits it into parameters [uncited]. The constructors lowercase nothing [src: commonMain/io/github/aughtone/types/uri/Url.kt:45], and all of `Url`'s components except `port` are required arguments [src: commonMain/io/github/aughtone/types/uri/Url.kt:22] [src: commonMain/io/github/aughtone/types/uri/Url.kt:30].

**Equality follows the RFCs, not the fields.** `Url` compares scheme and host case-insensitively [src: commonMain/io/github/aughtone/types/uri/Url.kt:53] [src: commonMain/io/github/aughtone/types/uri/Url.kt:54], and `Uri` the scheme and the whole authority [src: commonMain/io/github/aughtone/types/uri/Uri.kt:64] [src: commonMain/io/github/aughtone/types/uri/Uri.kt:65]. `Urn` compares the namespace case-insensitively and ignores the r-, q- and f-components entirely [src: commonMain/io/github/aughtone/types/uri/Urn.kt:119], so `urn:isbn:0451450523#page1` equals `urn:isbn:0451450523` [src: commonMain/io/github/aughtone/types/uri/Urn.kt:115]. `GeoUri` treats a missing `crs` and `wgs84` as the same [src: commonMain/io/github/aughtone/types/uri/GeoUri.kt:73]. Hashing follows the same rules [src: commonMain/io/github/aughtone/types/uri/Urn.kt:124], so the symptom is a `Set` or map holding fewer entries than were put in. The values given are still stored and serialized as given [src: commonMain/io/github/aughtone/types/uri/Urn.kt:117].

**`UrlBuilder.build()` returns a `String`, not a `Url`** [src: commonMain/io/github/aughtone/types/uri/UrlBuilder.kt:98], and throws `IllegalStateException` unless both `scheme` and `host` are set [src: commonMain/io/github/aughtone/types/uri/UrlBuilder.kt:101]. Each path segment is percent-encoded whole [src: commonMain/io/github/aughtone/types/uri/UrlBuilder.kt:65], and `/` is not in the unreserved set [src: commonMain/io/github/aughtone/types/uri/UrlEncoder.kt:18], so `addPathSegment("api/v1")` produces `api%2Fv1`; `addPathSegments("api", "v1")` adds two segments [src: commonMain/io/github/aughtone/types/uri/UrlBuilder.kt:75]. Repeating a query parameter name appends rather than replaces [src: commonMain/io/github/aughtone/types/uri/UrlBuilder.kt:81]. It has no fragment or user-information setter [uncited].

**Two encodings, not interchangeable.** `UrlEncoder.encode` follows RFC 3986 and writes a space as `%20` [src: commonMain/io/github/aughtone/types/uri/UrlEncoder.kt:7]; `encodeFormData` writes it as `+`, leaves `*` bare and encodes `~` [src: commonMain/io/github/aughtone/types/uri/UrlEncoder.kt:12]. `decode` keeps a `+` as a literal plus [src: commonMain/io/github/aughtone/types/uri/UrlEncoder.kt:96]; `decodeFormData` turns it into a space [src: commonMain/io/github/aughtone/types/uri/UrlEncoder.kt:107]. Both decoders throw `IllegalArgumentException` on a malformed percent sequence or invalid UTF-8 [src: commonMain/io/github/aughtone/types/uri/UrlEncoder.kt:100] [src: commonMain/io/github/aughtone/types/uri/UrlEncoder.kt:111]. The symptom of mixing them is a literal `+` where a space was meant [src: commonMain/io/github/aughtone/types/uri/UrlEncoder.kt:96].

**A `geo:` link gains `;crs=wgs84` on the way through.** `GeoUri`'s `crs` defaults to `"wgs84"` [src: commonMain/io/github/aughtone/types/uri/GeoUri.kt:32], the parser fills in the same default when the parameter is absent [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:202], and `toString` writes any non-null `crs` [src: commonMain/io/github/aughtone/types/uri/GeoUri.kt:130] — so `geoUri("geo:1,2").toString()` is `geo:1,2;crs=wgs84`. Passing `crs = null` omits it [src: commonMain/io/github/aughtone/types/uri/GeoUri.kt:130]. Unknown parameters are dropped on parsing [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:197], and the uncertainty `u` must be an integer [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:195].

### Outcome

**The payload is `data`, not `value`** [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:46]. The rest is shaped like `kotlin.Result`: `isSuccess`, `isFailure`, `getOrNull`, `getOrThrow`, `exceptionOrNull`, `fold`, `map`, `mapCatching`, `onSuccess`, `onFailure`, and `recover`, `getOrElse` and `getOrDefault` as extensions [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:10]. `Failure.message` is extra and never `null` [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:70].

**`map` does not catch.** An exception thrown by its transform propagates to the caller [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:141]; `mapCatching` captures it as a `Failure` [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:164]. `runOutcome` and `mapCatching` both re-throw `CancellationException`, so coroutine cancellation is never swallowed [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:206] [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:156]; `runOutcome` is `inline` and not `suspend`, so it can wrap suspending calls [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:192].

**Two failures are equal only if they hold the same exception instance** [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:54]. The symptom is a test comparing two separately built `Failure` values and failing; the source says to assert on the exception's type or message instead [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:56]. `Outcome` is deliberately not `@Serializable` — `fold` it into a serializable type first [src: commonMain/io/github/aughtone/types/outcome/Outcome.kt:31].

### Units and collections

**`UnitOfMeasure` names units; it converts nothing** [src: commonMain/io/github/aughtone/types/units/UnitOfMeasure.kt:28]. `findFirst(symbol)` returns `null` both for an unknown symbol and for an ambiguous one — `"gal"` is claimed by `Gallon` and `GallonImperial` [src: commonMain/io/github/aughtone/types/units/UnitOfMeasure.kt:166] — and `findAll(symbol)` tells the two apart [src: commonMain/io/github/aughtone/types/units/UnitOfMeasure.kt:175]. Lookup is case-sensitive: `GB` and `Gb` are different units, so lower-casing input first breaks it [src: commonMain/io/github/aughtone/types/units/UnitOfMeasure.kt:25]. The byte multiples are named on the binary reading and lead with the IEC symbol, so `Kilobyte.symbol` is `KiB` with `kB` as an alternative [src: commonMain/io/github/aughtone/types/units/UnitOfMeasure.kt:83].

**`BitSet` has a fixed size and does not grow** [src: commonMain/io/github/aughtone/types/util/BitSet.kt:10]. `BitSet()` holds one bit [src: commonMain/io/github/aughtone/types/util/BitSet.kt:16] and `bitSet()` none [src: commonMain/io/github/aughtone/types/util/BitSet.functions.kt:7]; setting or reading an index at or past the size throws `IndexOutOfBoundsException` — "Index: 5, Size: 1" [src: commonMain/io/github/aughtone/types/util/BitSet.kt:110]. `size()` is a function, and `hasIndex(i)` tests a position without throwing [src: commonMain/io/github/aughtone/types/util/BitSet.kt:98] [src: commonMain/io/github/aughtone/types/util/BitSet.kt:120].

**`LazyMap` value functions must be pure.** It is safe for concurrent access, but under contention a function may run more than once for one key, the loser's result being discarded [src: commonMain/io/github/aughtone/types/util/LazyMap.kt:28]. `equals` and `hashCode` may force every value [src: commonMain/io/github/aughtone/types/util/LazyMap.kt:21]. `lazyMapOf("key" to { compute() })` builds one [src: commonMain/io/github/aughtone/types/util/LazyMap.functions.kt:11].

## What moved, and what it used to be called

The published source records few changes, and gives a version for only one of them [uncited]; nothing below about earlier versions goes beyond what it states.

**Silent change first: on Linux, localized locale names started existing in 4.1.0.** Before 4.1.0 `localizedDisplayNameForNative` returned `null` for every pair on that target; it now answers from a bundled table [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:246] that ships only in the Linux artifact [src: linuxMain/io/github/aughtone/types/locale/Locale.functions.linux.kt:25]. Code that relied on always getting the English fallback from `localizedDisplayName` on Linux now gets translations [src: commonMain/io/github/aughtone/types/locale/Locale.functions.kt:210].

**`Location` is deprecated in favour of `Telemetry`**, same package `io.github.aughtone.types.quantitative`, same properties [src: commonMain/io/github/aughtone/types/quantitative/Telemetry.kt:47] [src: commonMain/io/github/aughtone/types/quantitative/Telemetry.kt:49]. `Location` still exists and compiles with a deprecation warning [src: commonMain/io/github/aughtone/types/quantitative/Telemetry.kt:52]. The source gives no version for the change [uncited].

**`Money.cents` is the old name for `Money.minorUnits`**, kept for backward compatibility [src: commonMain/io/github/aughtone/types/financial/Money.kt:84] and not marked deprecated [uncited].

**`GeoBoundingBox` used to extend `GeoGeometry` and no longer does** [src: commonMain/io/github/aughtone/types/geo/GeoBoundingBox.kt:14]. Passing one where a geometry is expected, as an earlier version allowed, does not compile; its numbers go in a geometry's or feature's `bbox` via `toBbox()` [src: commonMain/io/github/aughtone/types/geo/GeoBoundingBox.kt:18]. The source gives no version for the change [uncited].

The shapes most likely to be written from habit, each contradicted above: `outcome.value` (it is `data`), `java.math.BigDecimal` methods on `Money.value`, `Locale("en", "US")`, `GeoPoint(latitude, longitude)`, `UrlBuilder().build()` as a `Url`, and a `BitSet` that grows.

## What it is not for

The published source cannot say where the authors draw the line, so this section is only what the code itself shows.

It does not convert between units: `UnitOfMeasure` is names and symbols only [src: commonMain/io/github/aughtone/types/units/UnitOfMeasure.kt:28], and the measurement types are fixed to metres and metres per second [src: commonMain/io/github/aughtone/types/quantitative/Distance.kt:19] [src: commonMain/io/github/aughtone/types/quantitative/Speed.kt:19]. It has no function that formats a `Money`, a number, a distance or a date for display, and none that converts between currencies [uncited]. `Uri` and `Url` parse and compare but do not resolve dot segments or decode percent-encoding for you [src: commonMain/io/github/aughtone/types/uri/UriParsing.kt:76]. The bundled locale table is maintained by hand and is not Unicode CLDR data [src: commonMain/io/github/aughtone/types/locale/Locale.resource.kt:6].
